# 직업체험 공통 런타임 검토 v001

기준은 저장소 `AGENTS.md`입니다. 이 문서는 이번 구현·검토 결과이며 별도 규칙 원장이 아닙니다.

## 실제 구현 범위

- 하나의 프로젝트·판정·데이터·공통 브리지를 두 WebGL 빌드 모드가 공유합니다. 외부 시작은 방·시나리오·버전의 정확한 조합으로 선택합니다.
- 세 물건의 실제 메시·콜라이더 연결을 시작 전에 확인합니다. 작업 초안·저장본·요청 revision·전체 초기화 generation을 구분하며 닫기는 초안을 유지합니다.
- 세 통신 계열의 실행 ID 점유와 종료 영수증을 공유합니다. 같은 종료 요청은 원본 JSON/eventId를 재전달하고, 종료 후 새 종료 요청에는 원본 eventId와 ALREADY_ENDED를 반환합니다.
- interaction.progress는 200ms 간격으로 병합합니다. 간격 안에 닫기·제출·변경·종료가 발생하면 마지막 입력을 해당 전이의 data.coalescedProgress에 보존합니다. 오류·완료·중단·revision 변경 이벤트는 각각 발행합니다.
- 단계·물건·업무 항목·입력 당시 requestRevision과 draft revision이 병합 입력에 남습니다. 타이머 시작도 같은 경로를 사용합니다.

## 검사 근거와 한계

`docs/machine/evidence/career-suite-all-rules-v002.json`은 실제 소스의 상태·원장 코드를 메모리에서 실행한 검사입니다. 입력을 직접 구성했으며 Unity 화면·포인터·실제 통신 검수가 아닙니다. 544개 설정 중 사진 4개를 제외한 540개 기본 정상 경로와 544개 오류/재시도 집계·초기화·시간 정지 조건을 확인했습니다. 실제 사진 파일을 만들어 통과시키지 않았습니다. 설정된 요청 변경은 8개이며 나머지는 해당 검사의 대상이 아닙니다. 200ms 간격, 닫기 8회, 제출 입력 보존, 변경 전 revision 입력 보존, 타이머 시작 입력 보존을 별도로 확인했습니다.

`docs/machine/evidence/career-suite-test-v004/http-runtime-api-038-full-bindings.json`은 중간 v004의 실제 HTTP WebGL에서 수행한 38개 정확한 시작·세 물건 연결·시작 전 종료 검사입니다. 업무 완료·오류 복구·최종 빌드 실행을 대체하지 않습니다. 최종 빌드 실행 기록은 해당 빌드의 별도 증거를 기준으로 합니다.

## 미해결 계약 이슈: 이미 끝난 기존 사무실의 탐색 이벤트

대상은 `CareerProtocol.OnRoomChanged`와 `OfficeTenProtocol.OnRoomChanged`입니다. 사무보조원 또는 기존 사무실 10개 계열의 체험이 종료되어 Session과 RunId가 남은 뒤, 다른 물리 장면으로 이동하거나 PAN-001로 돌아오면 탐색 분기에 Ended 차단이 없어 **이전 종료 체험**의 scene.exited 또는 scene.entered 원본 이벤트가 추가될 수 있습니다.

기존 최종 영수증 JSON/eventId와 그 안의 과정 횟수는 바뀌지 않습니다. 업무 오류·재시도·완료를 새로 생성하는 현상도 아닙니다. 그러나 종료 후 원본 탐색 이벤트가 더 생기는 것은 닫힌 범위의 원장을 더 이상 확장하지 않는 계약과 다릅니다. 현재 화면의 새 체험과 이전 체험의 식별자를 구분해야 하며, 프론트의 현재 체험 필터가 원본 원장의 이 문제를 해결한 것으로 간주해서는 안 됩니다. 이번 최종 빌드 중 소스를 다시 바꾸지 않고 알려진 문제로 남겼습니다.

다음 수정에서는 물리 방 추적은 유지하되, Ended인 기존 사무실 체험의 탐색 이벤트 발행을 건너뛰는 방식으로 보완하고 교차 계열 이동을 실제로 재검수해야 합니다.

## 완료로 간주하지 않는 범위

전체 원래 전문 업무·특수 분기·직업별 전문가 정답·모든 입력 방식의 개별 실행 검수는 완료되지 않았습니다. 3D 프린팅 과제는 실제 프린터 운전이 아닌 설계 구성 검토·인계 준비의 하위 과제입니다. 실제 외부 백엔드의 인증·소유권 lease·fence·v003 정산 실행 역시 이 런타임 검토의 통과 범위가 아닙니다.
## 최종 v006의 실제 실행 검사

후반 36개 공간 PAN-036~PAN-071에서 공간당 정확한 ID·버전 조합 하나씩 실제 HTTP WebGL로 시작하고, 현재 실행의 메시·표시 상태·콜라이더가 연결된 조작 물건 세 개를 확인한 뒤 시작 전 종료했습니다. 36개 모두 통과했으며 각 실행의 원본 시작·종료 응답과 실제 표시 진단은 `docs/machine/evidence/career-suite-test-v006/http-room-runtime/`에 개별 저장했습니다. 업무 수행이나 다른 시나리오를 검수한 것으로 확대하지 않습니다.

데이터베이스관리자 PAN-060 / career-net-431-experience / v003은 실제 화면에서 세 업무를 끝냈습니다. 원본 근거는 `docs/machine/evidence/career-suite-test-v006/http-db-ui-complete-v001.json`, 완료 화면은 같은 폴더의 `db-ui-completed-v001.png`입니다. 직접 상태를 바꾸거나 가짜 완료 데이터를 만들지 않았습니다.

- 실제 관리 단말 선택, 한국어·시각 필드 입력, 닫기·재열기 후 미저장 초안 유지, 원래 카메라·뷰포트 복귀를 확인했습니다.
- 케이블 세 카드를 실제 포인터로 끌어 대응 위치에 놓고 저장했습니다.
- 보존기간·복사본 두 설정이 틀린 **한 번의 제출**을 실행했습니다. 두 오류 코드가 한 failureId에 들어가 실수는 1회로 집계됐습니다.
- 실제 슬라이더를 소수 위치로 끈 뒤 정수 7로 맞춰지는 동작과 −로 6, +로 7에 복귀하는 동등 조작, 복사본 2개 설정을 확인했습니다.
- 수정한 재제출로 세 업무가 완료됐고, 최종 종료도 completed를 유지했습니다. 실제 과정은 attemptCount 4, mistakeCount 1, retryCount 1, repeatedMistakeCount 0, navigationBackCount 4입니다. 입력 편집이나 팝업 복귀를 제출·실수로 세지 않았습니다.

### 실제 확인한 선택·표시의 사용성 한계

PAN-060의 얇은 케이블 트레이는 Renderer bounds 중앙을 클릭해도 선택되지 않았습니다. 보이는 표면을 다시 클릭한 시도는 뒤의 서버 랙을 열었습니다. 해당 시점의 서버 랙은 선행 단계가 잠겨 있어 제출되지 않았고 업무 실수도 증가하지 않았습니다. 키보드 2번의 동등 선택으로 케이블 작업을 계속해 정상 완료했습니다. 이 사례를 세 물건 모두의 포인터 선택 통과로 보고하지 않습니다. 세부 선택 영역·시점 보정이 필요합니다.

현재 SlotLabel은 slotLabel이 비어 있으면 순번 자리 이름을 사용하고, 이전 자료의 targetLabel을 표시 이름으로 사용하지 않습니다. 실제 프린팅 준비 과제의 상부·기초·벽체가 순번 자리로 보이는 문제가 보고됐습니다. 안내문과 동등 조작으로 진행할 수 있지만 덜 직관적이며, 다음 수정에서 slotLabel → targetLabel → 순번의 호환 표시를 검토해야 합니다. 이번 최종 빌드 소스를 바꾸지는 않았습니다.

## v007 소스 갱신 참고 — 실제 v006 검수와 구별

위 순번 자리 표시 문제는 v006에서 실제 관찰한 과거 상태다. 이후 v007용 소스는 `slotLabel → targetLabel → 순번` 호환 표시를 적용하고 두 줄 줄바꿈 및 같은 목표 이름의 힌트 표시를 추가했다. 소스 프로브의 WebGL 컴파일은 오류·경고0이고 음향 부수 채널10개 사례를 검사했다. 이것은 새 빌드의 실제 UI 표시·재생 검증을 뜻하지 않으며, 원본 v006의 관찰 기록을 수정하거나 통과로 바꾸지 않는다. 근거: 최종 우선순위 검사를 포함하고 검사 당시8개 소스 해시를 보존한 `docs/machine/evidence/career-suite-audio-source-probe-v003.json`. v002는 우선순위 갱신 전의 과거 검사다.

### 이후 카드 목적지·저장 결과 표시 소스 갱신

최종 v008/v004용 소스는 모든 공간 목적지의 드롭 강조와 정답 판정 전의 공간 배치 체크를 표시하고, 저장 결과 제목·본문을 CalcHeight로 분리해 긴 본문을 스크롤한다. Pilot의 배치 상태 줄620~648과 카드 저장 버튼650~690은2px 간격으로 분리했다. 독립 정적 검토에 새 겹침은 없었으며 실제 브라우저 검수는 해당 새 빌드 증거를 따른다. 음향 프로브v003 이후 바뀐3개 뷰 파일은 UI 표시만 수정한 것으로, v003의8개 해시가 현재 전체와 일치한다고 보고하지 않는다. 근거는 `career-suite-card-result-source-v001.json` 및 `career-audio-v002/card-layout-independent-review-v001.json`이다.
