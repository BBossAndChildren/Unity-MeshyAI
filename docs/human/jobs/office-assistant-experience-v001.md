# 사무보조원 — 요청에 맞는 문서 출력·보관 v001

## 근거와 목표

- 직업: 사무보조원, career-net-253. 기존 직업 catalog 기준.
- 원본: [Job_things_list.txt](sources/job-things-list/v001/Job_things_list.txt), `/items/190/data`. 하는일은 문서 수발·정리·복사·자료 입력 및 오류 수정, 핵심능력은 대인관계능력이다.
- 체험 각색: 동료의 모호한 출력 요청을 확인하고 문서 오류를 고친 뒤 출력·보관한다. 인물·조직·문서 내용과 정답은 가상의 교육용 설정이다.
- 역량 연결: 확인 질문으로 요청을 정확히 이해하고 처리 결과를 요약해 전달한다. 문서 정리는 업무 수행 활동이며 원본 핵심능력을 임의로 손재능으로 바꾸지 않는다.
- 장소: PAN-001 v001, 공용 업무 사무실. PRM-001 v001, office-shared-work v001의 기존 사무보조원 연결을 따른다. 직업·장소 사실 검증은 미검증.
- 3D 배경 기준: AST-020 v003, pan-001-office revision 2의 기존 조립 기록·placements. 기존 검수 기록상 4,308삼각형이며 이번에 재측정하지 않았다. 추가 오브젝트와 UI를 포함한 최종 장면 예산은 구현 후 다시 측정한다.
- 초기 명세 작성 시점: 기획 명세만 작성되었고 실행은 미검증이었다. 최신 구현·실행 결과는 아래 2026-10-31 기록을 따른다.

## 하나의 미션

시작 안내: “동료가 회의자료를 출력해 달라고 합니다. 빠진 요청을 확인하고, 수정한 자료를 필요한 만큼 출력한 뒤 회의자료 칸에 보관하세요.”

가상 요청 ID는 REQ-001, 최종 문서 DOC-001의 제목은 ‘팀 회의자료’, 회의일은 ‘11월 2일’, 보관 분류는 ‘회의자료’다. 날짜·부수는 업무 사실이 아니라 게임의 정답 데이터다. 기본 경로는 2부, 돌발 변경 경로에서는 출력 전에 3부로 바뀐다.

화면 UI에는 요청 카드·대화·문서 편집·분류 라벨을 표시한다. UI는 네 번째 3D 상호작용 물건으로 세지 않는다. 실제 사람 NPC나 휴대전화 에셋을 추가하지 않는다.

## 상호작용 물건 3개

| 물건 | 후보 및 실제 모델 재사용 참조 | 필요한 3D 반응 | 배치 |
|---|---|---|---|
| 업무 모니터 | CND-005 → AST-005 v001 | 선택 윤곽, 화면 앞 UI, 편집 결과 갱신 | 기존 업무석 중 하나만 활성화 |
| 복합기 | CND-008 → AST-009 v001 | 선택, 동작 표시, 출력 대기·완료 상태 | 기존 공용 출력 위치 |
| 뒤쪽 수납장 | CND-009 → AST-015 v001 | 선택, 문서 분류 칸 선택, 보관 완료 표시 | 기존 후면 수납 위치 |

고정 v003의 전체 scenes.required_candidate_ids를 대조한 결과, 모니터는 14개 공간·수납장은 13개 공간의 공통 후보이며 복합기는 1개 공간의 비공통 후보다. 기존 사무실 계획의 프린터·복합기 제품군 재사용 의도와 개별 CND-008의 현재 공간 연결 수는 구별한다. 이후 다른 공간에 같은 후보를 연결하면 새 명세 버전에서 분류를 다시 계산한다. 현 버전 메시가 화면·용지·문짝의 분리 애니메이션을 지원한다고 가정하지 않는다. 최소 구현은 콜라이더와 UI·상태 표시로 가능하다. 분리 문짝이나 움직이는 용지가 꼭 필요하면 새 모델 버전을 제작하고 삼각형을 다시 측정한다. 출력 문서는 논리적 소지 상태로 관리해 상호작용 물건을 늘리지 않는다.

## 단계·판정·재시도

| 단계 | 물건·유형 | 행동 | 성공 조건 | 오류·복구 |
|---|---|---|---|---|
| 1 요청 확인 | 모니터 / MG-008 | ‘어떤 자료인지’, ‘몇 부인지’를 확인하고 요청을 요약한다. | DOC-001·부수·보관처 확인 뒤 동료 확인 응답 | 추측해서 인쇄하려 하면 빠진 정보를 알려주고 질문으로 복귀 |
| 2 문서 검토 | 같은 모니터 / MG-005 | 요청의 회의일 11월 2일과 문서의 잘못된 날짜 11월 1일을 비교하고 수정한다. | 날짜를 정확히 고쳐 새 문서 revision을 저장 | 제목만 수정하거나 미저장 시 수정 위치·저장 필요 안내 |
| 3 출력 | 복합기 / MG-003 | 저장된 최신 문서를 골라 확인된 부수로 출력한다. | 요청과 문서 revision 일치, 정확한 부수, 완료 이벤트 1회 | 잘못된 파일·부수는 출력 전 경고. 반복 클릭은 작업 중 잠금 |
| 4 보관·인계 | 수납장 / MG-001 + EX-008 | 출력 묶음을 ‘회의자료’ 칸에 넣고 처리 결과를 동료에게 전달한다. | 정확한 분류와 문서·부수·날짜가 맞는 인계 확인 | 잘못된 칸은 보관 확정하지 않고 이유 설명. 정답 전 자유 재선택 |

4단계지만 조작하는 3D 물건은 3개다. 진행 상태는 `request_pending → request_confirmed → document_saved → printing → print_ready → filed → complete`다. 인쇄 전 서류함 선택 등 순서 위반은 상태를 바꾸지 않는다. 각 상태를 두 번 클릭해도 출력·점수가 중복되지 않는다.

## 특수 상황 분기

- EX-007 돌발 변경: 문서 저장 직후, 출력 전에 동료가 2부에서 3부로 변경한다. 요청 revision이 증가하고 확인 상태가 해제된다. 같은 모니터에서 변경 내용을 재확인한 뒤 3부를 출력한다. 기본 경로와 변경 경로의 정답을 섞지 않는다.
- EX-008 협업·인계: 출력만으로 완료하지 않는다. 수납장 보관 후 ‘팀 회의자료 / 11월 2일 / 요청 부수 / 회의자료 칸’을 요약하고 확인 응답을 받아 완료한다. 기본 경로에 포함한다.
- EX-010 기록·추적·복구: 인쇄 전에 문서 날짜를 다시 잘못 바꾼 경우 이력에서 올바른 저장본으로 복구하는 선택 연습이다. 복구도 새 revision이며 과거 기록은 유지한다. 초기 구현에서는 선택 연습으로 분리할 수 있으며 미구현이면 구현 완료로 세지 않는다.

## 완료 화면과 수용 기준

요청 확인·문서 정확성·출력 조건·분류 및 인계 결과를 각각 보여준다. 틀린 선택에는 이유와 다시 하는 방법을 제공한다. 실제 직업 능력 점수나 적성 판정을 내리지 않는다. 시간은 설명용이며 속도 경쟁으로 평가하지 않는다.

실제 3D 사무실에서 세 물건을 선택해 진행할 수 있어야 한다. 물건 선택으로 열리는 UI는 해당 물건에 연결되어야 하며, 목록 버튼만 눌러 완료하는 흐름으로 대체하지 않는다. 카메라 회전·확대와 선택이 충돌하지 않아야 한다.

필수 확인: 기본 성공 경로, 잘못된 날짜, 잘못된 부수, 잘못된 보관 칸, 순서 위반, 변경 요청 경로, 출력 중 반복 클릭, 완료 후 재클릭, 전체 초기화. 각 항목은 실제 실행 후 근거와 함께 기록한다. 초기 명세 작성 시점에는 모두 미검증이었다. 최신 결과는 아래 구현·검증 기록을 따른다.
