# 파노라마 기반 직업체험 구성 명세 v001

## 구성의 기준

우리는 파노라마를 기준으로 필요한 에셋을 공통 에셋과 비공통 에셋으로 분리하여 명세하고, 해당 파노라마의 공간 의미·배치 관계를 기준으로 3D 장면을 구성한다. 같은 장소를 공유하는 직업들은 장면과 에셋을 재사용하며, 그 장소 안에서 직업별 업무·핵심역량을 반영한 상호작용을 수행한다. 직업체험은 물건 3개와 하나의 연결된 미션으로 구성하고, 공통 미니게임 10종과 특수 상황 규칙 10종을 조합한다.

파노라마는 장면 구성 참고도다. 화면에 그림만 띄우는 방식과 실제 3D 장면을 구별한다. 직업 원장은 기존 552개 직업 catalog이며, 업무·역량은 보존 원본으로 추적한다. 원본이 제공한 설명과 게임용으로 각색한 사건·수치·정답을 구별한다. 규칙·데이터 계약의 단일 기준은 [AGENTS.md](../../../AGENTS.md)다.

## 공통·비공통 에셋과 장면

분류는 고정 버전의 전체 공간 후보에서 파생한다. 같은 후보 ID가 둘 이상의 서로 다른 공간에서 사용 후보로 연결되면 공통, 한 공간에만 연결되면 비공통으로 분류한다. 이는 재사용 계획상의 분류이며 실제 배치·완성 모델 수량을 뜻하지 않는다. 같은 범용 후보라도 분리 부품·구조가 달라지면 그 차이를 별도 명세하고 실제 파일은 버전 규칙을 따른다.

장면에는 세 상호작용 물건 외에도 책상·의자·조명 같은 배경 에셋을 배치할 수 있다. 배경 에셋은 상호작용 물건 수에 넣지 않지만, 전체 삼각형 예산에는 포함한다. 파노라마에서 시각적으로 보이는 것, 제작 후보, 실제 모델, 실제 배치, 빌드 포함, 실행 검증은 각각 구별한다.

## 연결 구조

`파노라마 ID·버전 → 공간별 공통/비공통 에셋 후보 → 실제 에셋 ID·버전 → 직업 ID → 시나리오 → 상호작용 물건 3개 → 미니게임 규칙 → 피드백`

직업에 맞는 파노라마를 선택한 이유와 기존 매칭의 상태를 남긴다. 기존 장소 분류 후보를 게임에 사용했다는 이유로 실제 근무지 사실 검증이나 기존 기획 승인을 자동 변경하지 않는다. 같은 직업이 여러 장소에서 일해도 처음에는 대표 업무 하나를 선택한다. 원문의 역량은 학습 활동을 설명하는 근거이며 플레이 결과를 직업 적성·능력 진단으로 사용하지 않는다.

## 재사용 미니게임

[기계용 20종 명세](../../machine/catalog/career-minigame-types-v001.json)의 MG-001~010은 기본 조작과 판정 방식이다. EX-001~010은 기본 조작에 덧붙이는 상황 분기다. 매 미션에 20종을 모두 넣지 않고 필요한 유형만 고른다. 특수 상황에서도 상호작용 물건 3개를 유지하며 추가 안내·상황은 UI로 제공할 수 있다.

## 우선 완료할 사무실 사례

[사무보조원 — 요청에 맞는 문서 출력·보관](office-assistant-experience-v001.md)을 첫 구현 대상으로 명세했다. 초기 작성 시점의 범위는 시나리오와 구현용 프롬프트 작성이었다. 이번 실제 구현·검증 결과는 아래 2026-10-31 기록과 최종 빌드 보고를 따른다.

기존 3D 사무실 조립본 AST-020 v003을 배경 기준으로 재사용하고 모니터·복합기·뒤쪽 수납장을 실제 3D 선택 대상으로 삼는다. 전체 직업 확장은 첫 사례의 사용성 확인 뒤 진행한다. 현재 시나리오 작성 1개, 나머지 551개는 작성 대기다. 20종은 설계 목록이며 전체 구현 완료를 뜻하지 않는다. 이번 구현한 부분과 남은 범위는 아래 기록을 따른다.

## 2026-10-31 첫 구현 상태 갱신

위 문서의 기획 작성 시점 설명과 구분하여, 사무보조원 1건의 실제 구현·실행 결과를 [최종 WebGL 보고](../builds/office-assistant-v003.md)에 기록했다. 4개 공통 유형과 EX-007·008을 이 시나리오 범위로 구현했다. EX-010과 나머지 유형·551개 직업의 미구현 상태는 유지한다.
