# 물류관리사 배치 진행 오류 수정

사용자가 보고한 1단계 실패를 기존 career-pilot-v005의 실제 HTTP WebGL에서 재현했다. 화면에 보이는 칸의 세로 반경은 0.10이지만 원시 좌표 판정 허용치는 0.065여서, 보이는 칸 안에 놓아도 실패했다. 안내의 북부·동부·남부와 화면의 번호만 있는 칸도 일치하지 않았다. 이전 자동 검수는 목표 정중앙 드롭에 치우쳐 이 문제를 놓쳤다.

career-pilot-v007은 실제 포인터가 들어온 칸의 중심으로 배치한다. 물건의 정답 목적지로 자동 이동시키지 않으므로 잘못된 칸은 계속 거절한다. 드래그를 시작한 카드 안 위치를 유지하고, 클릭만 한 경우에는 좌표를 바꾸지 않는다. 명시적 선택 버튼 다음 목적지 클릭은 점유된 칸에서도 선택한 카드를 배치한다. 칸에 목적지와 화물 이름을 표시하고 선택 후 4·5·6키 대체 입력, 저장 후 다음 물건 안내를 제공한다.

실제 v007 검수에서 1단계 가장자리 드래그, 2단계 오답 후 점유된 칸 재배치, 3단계 키보드 배치와 최종 completed 응답을 통과했다. 각 단계 오답 1회·재시도 1회가 정확히 기록됐고 클릭만 한 카드는 움직이지 않았다. [원본 검수](../../machine/evidence/career-pilot-v007/logistics-regression/pilot-http-acceptance.json), [수정 전 재현 및 원인](../../machine/evidence/logistics-placement-fix-v001/investigation.json).

수정 파일은 고정 빌드 사본의 PilotRuntime.cs, PilotSession.cs와 career-pilot-content.json이다. 모델·팔레트·원본 정답·허용오차·통신 규격은 변경하지 않았다. 모델 생성·Meshy 호출·크레딧 0, 실제 대화 토큰과 순수 노력 시간은 도구에서 제공되지 않아 null이다. Windows Chrome SwiftShader 실행이며 실물 모바일 기기와 다른 브라우저는 미검증이다.
