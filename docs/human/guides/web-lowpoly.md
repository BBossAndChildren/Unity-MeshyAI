# 웹용 로우폴리 제작 — 사람용 요약

이 문서는 작업 요청과 결과 검수용 요약입니다. 상세 기준은 [AGENTS.md의 웹용 로우폴리 제작 규칙](../../../AGENTS.md#7-웹용-로우폴리-제작-규칙)을 따릅니다. 규칙 변경 시 이 요약도 함께 갱신합니다.

## 먼저 정할 것
개별 소품인지 디오라마인지 구분하고 참고 이미지, 대상 웹 환경, 도구 사용 가능 여부와 승인된 크레딧 범위를 확인합니다.

| 항목 | 기준 |
|---|---|
| 개별 소품·단순 캐릭터 | 눈·입·장식 등 모든 부품 합산 1,000삼각형 이하 |
| 디오라마 | 전체 5,000삼각형 목표; 내부 소품도 각각 1,000 이하 |
| 반복 배치 | 소품 삼각형 수 × 배치 횟수를 전체에 포함 |
| 측정 기준 | 최종 GLB를 다시 열어 측정; 편집 화면의 사각형 면 수와 구분 |
| 기본색 | color1 원본의 파스텔 색; 피부·옷·몸통·지형 등 넓은 면 |
| 강조색 | color2 원본의 원색·대비색; 눈·입·강조선·작은 장식 |
| 실제 텍스처 | 두 원본의 칸을 담은 정사각형 PNG 한 장 |
| 재질 | 모든 부품이 공용 재질 사용; 흰색 배율, 추가 착색·불필요한 이미지 맵 금지 |
| 용량 | 실제 GLB 바이트 수 보고; 합의 없는 고정 상한 금지 |

## 제작 흐름
참고 자료·재사용 결과 확인 → 도구 선택 → Blender 직접 제작 / Meshy 생성 / 부품별 혼합 → Blender 최적화·조립 → 공용 팔레트·UV 적용 → GLB 저장·재열기 → 실제 웹 검수.

## Blender와 Meshy 선택 기준

| 선택 | 적합한 작업 |
|---|---|
| Blender 직접 제작 우선 | 기본 도형·매개변수로 정의되는 형태, 정확한 치수·대칭·간격, 기존 스크립트 재사용 |
| Meshy 검토 | 캐릭터·동물·조형물의 자유로운 곡면과 독특한 실루엣, 직접 제작·교정 부담이 큰 형태 |
| 혼합 | 유기적 부분은 Meshy, 구조물·받침대·반복 배치·전체 조립은 Blender |

바닥판·표면·타일·러그, 상자·책·서류 묶음, 단순 가구·모니터·간판, 반복 프레임·기둥은 Blender 우선 후보입니다. 종류만으로 고정 분류하지 않습니다.
에이전트는 복잡도보다 형태의 특성을 우선합니다. 반복·대칭·정확한 치수·명확한 부품 구성은 Blender, 유기적 형태·불규칙한 실루엣·자유로운 곡면은 Meshy를 우선합니다. 복잡해 보여도 기본 도형과 반복 구조로 표현할 수 있으면 Blender를 우선합니다. 재사용성·수정 부담도 고려하여 승인된 작업 범위 안에서 별도 확인 없이 선택하고 이유를 한두 문장으로 기록합니다.
Meshy는 승인된 크레딧만 사용하며 유료 재생성을 자동 반복하지 않습니다. 먼저 Blender 수정 가능성을 검토합니다. 최종 팔레트·UV·GLB 작업은 Blender에서 수행합니다.

### 베타 비교에서 얻은 기준

사용자가 제공한 결과 및 [기준 문서의 베타 비교 기록](../../../AGENTS.md#베타-비교-기록과-해석) 기준입니다. 이 지침 갱신에서 재측정한 수치는 아닙니다.

| 대상 | 방식 | 삼각형 | Meshy 크레딧 |
|---|---|---:|---:|
| 기존 바닥판 | Meshy + Blender 교정 | 120 | 5 |
| 비교 바닥판 | Blender 직접 제작 | 220 | 0 |
| 바닥 표면 | Blender 함수 재사용 | 108 | 0 |

직접 제작은 상한 안에서 정확한 치수·모서리 반경과 형태 일관성을 확보하고 함수를 재사용할 수 있었습니다. 두 방식 모두 팔레트 UV와 GLB 웹 표시가 가능했다는 기록입니다.
약 3.3MB의 용량은 주로 공용 팔레트에서 발생했으므로 제작 도구 선택과 팔레트 용량 최적화는 별도입니다. 삼각형 수만으로 우열을 판단하지 않습니다.
모델별 토큰은 미측정이므로 절감 수치를 주장하지 않습니다. 실행 시간과 스크립트 작성·검수 시간도 구분합니다.

실루엣·표정의 가독성을 우선합니다. 둥근 디자인에는 부드러운 셰이딩을 사용하고 불필요한 내부 면·작은 디테일·잘못 연결된 부품을 정리합니다.
재생성 전에 기존 결과의 후처리 가능성을 검토하고 반복 소품을 재사용합니다.

## 색상에서 지킬 것
- color1.jpg와 color2.jpg는 원본 그대로 보존합니다.
- 원본 칸을 색 변화 없이 재배치한 palette.png를 사용합니다. 보간·보정·손실 압축·새 무늬·그림자 추가는 금지합니다.
- 원본 출처·행·열·최종 UV 위치를 mapping.json에 기록합니다.
- 면의 UV는 칸 중앙 또는 충분히 안쪽에 둡니다. 다른 색의 면은 UV를 분리합니다.
- 색상 변경은 UV 이동으로 우선 처리합니다. 사용 색상을 4개로 제한하지 않습니다.
- 조명 명암은 허용하지만 버텍스 컬러·재질 배율로 새 색을 추가하지 않습니다.
- 축소·원거리에서 색 번짐을 확인합니다. 공용 재질이라고 드로콜 하나로 단정하지 않습니다.

## 받을 결과물
- 최종 model.glb 및 Blender 수정본.
- 공용 palette.png와 원본·행·열·UV 대응표 mapping.json.
- 재사용 가능한 후처리 스크립트.
- inspection.json 검수 기록.

팔레트는 textures/palettes/<버전>/에 공유하고, 모델별 수정본·exports/·processing/·inspection.json은 해당 Blender 에셋 버전에 보관합니다.

- 제작 방식과 선택 이유·실제 결과, Meshy 실제 소비 크레딧, 재사용할 스크립트·모델, 다음 작업 개선점.
- 소품별 삼각형 수와 배치 횟수를 포함한 장면 전체 수.
- 재질·텍스처 수, 팔레트 해상도, 최종 GLB 바이트 수.
- GLB 재열기 검수 및 대상 웹의 로딩·외형·축소 표시 결과.
- 텍스처 누락·색 번짐·방향·크기 문제 여부.
- 미검증 항목, 남은 문제와 수정안.
- Blender 직접 제작의 원본 .blend·제작 스크립트 보존, Meshy 사용 시 프롬프트·작업 ID·비용 근거 기록.
- 일반 GLB 웹 표시와 Unity WebGL 빌드·실행 검증의 구분. Unity WebGL은 실제 빌드·실행한 경우에만 완료로 보고.

목표를 넘거나 검수하지 못했으면 완료로 표시하지 않습니다. 사용자 변경 지시가 없으면 기준을 임의로 완화하지 않습니다. 미리보기만으로 삼각형 수·용량·웹 성능을 검증했다고 판단하지 않습니다.
